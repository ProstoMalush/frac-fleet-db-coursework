# Архитектура решения

Проект включает **две исходные предметные области** и одну общую аналитическую схему.

- `frac_core` — операционная БД флотов ГРП, оборудования, ремонтов, этапов и технологической телеметрии.
- `partner_1` — самостоятельная БД замеров по скважинам с независимыми локальными идентификаторами.
- `frac_mart` — общий аналитический слой: звезда Кимбалла и представления, объединяющие два источника. Это не третья предметная область.

Локальные `frac_core.well.well_id` и `partner_1.source_well.source_well_id` не являются общим ключом. Для сопоставления применяется составной естественный ключ `(field_code, well_code)`. Контрольный набор намеренно содержит совпадающие числовые ID у разных скважин, чтобы продемонстрировать риск наивного JOIN по одному ID.

`frac_mart.dim_field` реализует SCD Type 2: при изменении атрибута создаётся новая версия месторождения с отдельным суррогатным ключом и периодом действия. Факт ремонта ссылается на версию измерения, действовавшую на дату ремонта.

Основные диаграммы: [`architecture.mmd`](architecture.mmd), [`conceptual_model.mmd`](conceptual_model.mmd), [`logical_model.mmd`](logical_model.mmd), [`physical_model.mmd`](physical_model.mmd), [`kimball_star.mmd`](kimball_star.mmd).
