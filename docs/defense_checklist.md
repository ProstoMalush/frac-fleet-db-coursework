# Краткая памятка для защиты курсовой

## 1. Постановка задачи

Разработана БД для учёта работы флотов ГРП при проведении ремонтных работ на скважинах. Она хранит месторождения, скважины, состав флотов, оборудование, бригады, ремонты, этапы и временные технологические измерения.

Все данные проекта синтетические и предназначены для демонстрации структуры и SQL.

## 2. Проектирование

- КМД показывает 12 сущностей и их связи.
- ЛМД описывает атрибуты, ключи и кардинальности.
- ФМД фиксирует типы PostgreSQL, PK, FK, CHECK, ограничения, индексы и комментарии.
- Операционные схемы нормализованы до 3НФ.
- В `normalization.md` показан пример широкой таблицы и устранение аномалий при переходе к 3НФ.

## 3. Объём данных

- `frac_core.telemetry_measurement`: 53 760 строк.
- `frac_core.well`: 100 скважин.
- `frac_core.well_repair`: 426 ремонтов, из них 420 завершённых.
- `partner_1.well_measurement`: 34 400 значений измерений.

## 4. SQL и функции

Пять бизнес-запросов отвечают на вопросы по ремонтам месторождений, производительности флотов, повторным ремонтам, технологическим параметрам и техническому обслуживанию. В запросах применены JOIN, агрегации, CTE, коррелированный подзапрос и оконные функции `DENSE_RANK`/`LAG`.

Создано 10 функций PostgreSQL. Для PL/pgSQL-функции расчёта процента использования предела давления проверены NULL, нулевой предел и обычный расчёт: 45 / 60 = 75%.

## 5. Индексы и производительность

- B-tree по `repair_stage.started_at`;
- составной частичный B-tree по `(frac_fleet_id, planned_start_at)` для плановых и выполняемых ремонтов;
- BRIN по `telemetry_measurement.measured_at`.

После физической сортировки телеметрии через `CLUSTER` корреляция `measured_at` составила 1,0. В контрольном запуске BRIN изменил план с `Seq Scan` на `Bitmap Index Scan` + `Bitmap Heap Scan`.

## 6. Витрина Кимбалла

`frac_mart.fact_well_repair` содержит 420 фактов. Измерения: календарь, месторождение и вид ремонта. `dim_field` демонстрирует SCD-2 на `SYN-FLD-001`: первая версия закрыта 2025-01-01, вторая действует с этой даты.

Витрина отвечает на вопросы о числе и продолжительности ремонтов по месторождениям, кварталам и видам работ.

## 7. Интеграция двух предметных областей

Сопоставлены `frac_core` и `partner_1`. Локальные числовые ID не используются как общий ключ; сопоставление выполнено по `(field_code, well_code)`. В тестовом наборе 100 из 100 пар имеют разные локальные числовые ID. Наивный JOIN только по ID дал 100 неверных пар.

Междоменное представление дополнило 420 фактов ремонтов последними корректными замерами в пределах 90 дней до ремонта.
