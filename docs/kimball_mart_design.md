# Аналитическая витрина по модели Кимбалла

## Назначение

Витрина `frac_mart` предназначена для квартального анализа завершённых ремонтов скважин, выполненных флотами ГРП. Она отвечает на вопросы: на каких месторождениях и в какие кварталы выполнялись ремонты, какие виды ремонтов проводились, сколько времени занимали операции и какие технологические показатели были получены.

Все исходные данные проекта синтетические. Демонстрационное изменение описания месторождения `SYN-FLD-001` создано специально для показа SCD Type 2 и не является реальным производственным событием.

## Зерно таблицы фактов

`fact_well_repair`: одна строка соответствует одному завершённому ремонту (repair_status = `completed`). Плановые и отменённые операции в таблицу фактов не загружаются.

В таблице фактов сохраняются меры:
- `repair_count` — счётчик событий, равный 1;
- `actual_duration_hours` — фактическая продолжительность ремонта;
- `stage_count` — количество этапов;
- `measurement_count` — количество телеметрических измерений;
- `avg_pressure_mpa` и `max_pressure_mpa` — среднее и максимальное давление по всем точкам телеметрии ремонта;
- `total_fluid_volume_m3` — сумма максимальных накопительных объёмов жидкости по этапам;
- `total_proppant_mass_t` — сумма максимальных накопительных масс проппанта по этапам.

Накопительные показатели агрегируются сначала до уровня этапа через `MAX`, затем суммируются по этапам. Это исключает многократное суммирование накопительного временного ряда.

## Измерения (3)

1. `dim_date` — календарное измерение: дата, год, квартал, месяц и день недели.
2. `dim_field` — месторождение с историей SCD Type 2. `field_key` — суррогатный ключ версии, `source_oil_field_id` — естественный ключ исходного месторождения. Периоды имеют вид `[valid_from, valid_to)`, `NULL` в `valid_to` означает текущую версию.
3. `dim_repair_type` — справочник видов ремонта.

`fleet_code` и `well_code` хранятся в факте как вырожденные измерения (degenerate dimensions), чтобы сохранить предусмотренные заданием 2–3 отдельных измерения.

## SCD Type 2

Функция `fn_apply_field_scd2_change` закрывает текущую версию (`valid_to = дата изменения`, `is_current = false`) и добавляет новую версию с новым `field_key`, `valid_from = дата изменения`, `valid_to = NULL`, `is_current = true`.

Для демонстрации скрипт `03_scd2_function_and_demo.sql` создаёт учебную версию описания для `SYN-FLD-001` с 2025-01-01. Имя и регион не меняются. Это искусственный пример механизма SCD-2; он явно помечен как синтетический.

Пересечение периодов для одного естественного ключа запрещается ограничением EXCLUDE USING GiST. Уникальный частичный индекс гарантирует не более одной текущей версии месторождения.

## Дата операции

Дата ремонта определяется из `actual_start_at` в часовом поясе `Asia/Yekaterinburg` (UTC+05), чтобы формирование календарного ключа не зависело от часового пояса клиентской сессии.

## Представления

- `v_quarterly_repairs_dashboard` — аналитическая агрегация по кварталу, версии месторождения и виду ремонта; основное представление для отчёта/дашборда.
- `v_repair_fact_detail` — построчная расшифровка каждой записи факта.

## Ожидаемый результат первоначальной загрузки

- `dim_field`: 11 строк (10 первоначальных версий + 1 новая версия SCD-2 для `SYN-FLD-001`);
- `dim_repair_type`: 8 строк;
- `fact_well_repair`: 420 строк (завершённые синтетические ремонты);
- `dim_date`: по одной строке на каждый календарный день диапазона завершённых ремонтов.

После загрузки `06_validate_mart.sql` должен показывать нулевое число пропущенных измерений и ноль фактов с неверно выбранной версией месторождения.
