# Этап 5. Обоснование пяти бизнес-запросов

## 1. Ремонты по месторождениям и кварталам

Связь `well_repair -> well -> oil_field` позволяет получить месторождение ремонта через скважину, не дублируя `oil_field_id` в таблице ремонтов. `date_trunc('quarter', actual_start_at)` группирует ремонты по кварталам. Рассчитываются число ремонтов, число уникальных скважин и средняя фактическая продолжительность.

## 2. Производительность флотов

Запрос агрегирует завершённые ремонты по флотам. Используются `COUNT`, `SUM` и `AVG`. Оконная функция `DENSE_RANK()` ранжирует флоты по суммарному фактическому времени ремонтов. Это не оценка качества работы и не KPI производственной эффективности: это учебный показатель накопленной занятости флота.

## 3. Повторные ремонты

Оконная функция `LAG()` в разрезе `well_id` возвращает код и дату завершения предыдущего ремонта. Разность между началом текущего и завершением предыдущего ремонта показывает интервал между ремонтами.

## 4. Измерения давления относительно среднего по этапу

Это коррелированный подзапрос: внутренний `SELECT AVG(...)` использует `m.repair_stage_id` из внешней строки. Он рассчитывает среднее давление конкретного этапа. Внешний запрос оставляет измерения, превышающие это среднее более чем на 3%. Порог условный и нужен для демонстрации аналитики, не норматив.

Некоррелированный вариант реализован в `07_telemetry_above_stage_average_noncorrelated.sql`: сначала CTE рассчитывает среднее давление для всех этапов (`GROUP BY repair_stage_id`), затем агрегат присоединяется к строкам измерений через `JOIN`. Среднее вычисляется отдельным набором групп и не зависит от текущей строки внешнего запроса. При одинаковом пороге и данных оба запроса должны возвращать одинаковые строки.

## 5. Оборудование и ТО

CTE разделяют логику на три части: текущие назначения оборудования, последняя запись ТО на единицу оборудования и итоговая выборка по флоту. Итог показывает количество закреплённых единиц, количество единиц с ограниченным статусом, просроченные ТО и ТО, срок которых наступит в течение 30 дней.

## Ограничения интерпретации

Все записи проекта синтетические. Результаты подходят для демонстрации проектирования, SQL и принципов аналитики, но не являются фактической оценкой производственных флотов или техническими рекомендациями.
