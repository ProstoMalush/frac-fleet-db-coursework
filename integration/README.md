# Интеграция двух предметных областей

Источники данных:
- `frac_core` — основная БД флотов ГРП и ремонтов скважин;
- `partner_1` — отдельная БД замеров по тем же учебным скважинам.

`frac_mart` — общий аналитический слой, а не третья предметная область.

Перед выполнением должны быть созданы и заполнены `frac_core`, `partner_1` и `frac_mart`.

Порядок:
1. `06_create_cross_domain_views.sql` — создать три представления в `frac_mart`.
2. `07_validation.sql` — проверить сопоставление и общую аналитику.

Сопоставление скважин выполняется по составному естественному ключу `field_code + well_code`. Локальные числовые ID в двух схемах независимы и не должны использоваться как общий ключ.

В представлении ремонтов подбирается последняя корректная измерительная сессия за 90 дней до точного времени начала ремонта. Если такой сессии нет, ремонт остаётся в результате, а поля замеров будут `NULL` благодаря `LEFT JOIN LATERAL`.

Все данные синтетические и предназначены для учебного проекта.
