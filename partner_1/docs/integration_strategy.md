# Интеграция partner_1 с frac_core и frac_mart

## Источники

- `frac_core` — операционная база флотов ГРП и ремонтов скважин.
- `frac_mart` — аналитическая витрина завершённых ремонтов.
- `partner_1` — независимая схема измерений по скважинам.

Все данные partner_1 синтетические. Коды `field_code` и `well_code` намеренно соответствуют учебному набору frac_core, чтобы показать междоменную интеграцию.

## Коллизии ID

Локальные `source_well_id` в partner_1 и `well_id` в frac_core назначаются независимо. В тестовом наборе оба диапазона содержат значения 1–100, однако порядки назначения ID различаются. Поэтому соединение только по числовому ID может сопоставить разные скважины.

Правильный ключ сопоставления:

`partner_1.source_field.field_code = frac_core.oil_field.field_code`

и

`partner_1.source_well.well_code = frac_core.well.well_code`

Оба условия применяются одновременно, потому что `well_code` уникален внутри месторождения, а не обязательно глобально.

## Междоменное представление

`frac_mart.v_repair_with_partner_well_measurements` сохраняет одну строку на один завершённый ремонт и добавляет последнюю корректную измерительную сессию по соответствующей скважине за 90 дней до точного времени начала ремонта.

`frac_mart.v_quarterly_repairs_with_well_measurements` агрегирует ремонты и замеры по кварталам, месторождениям и видам работ.

В представления включаются только сессии и отдельные измерения с качеством `valid`. Если подходящей сессии нет, поля партнёрских замеров будут NULL, но ремонт останется в результате благодаря LEFT JOIN LATERAL.
